  - **Blocker 1: port contract between values, container port, probes and Service (1.2).** `templates/deployment.yaml:47` sets `containerPort: {{ .Values.service.port }}`, and `values.yaml:56` says the value is "also the exporter listen port". Nothing passes the port to the exporter: there is no `--web.listen-address` in args, so it always listens on `[::]:9221`. With `service.port: 9300`, the named `http` port becomes 9300. The liveness/readiness probes (`values.yaml:67-80`, `port: http`) and the Service `targetPort: http` then all point at a port where nothing listens, and the pod crash-loops. The test `deployment_test.yaml:43-49` ("follows service.port for the container port") locks this behaviour in instead of catching it. No single template is wrong by itself. The fault is the chain: Service port → container port → probe → exporter listen address. Section 3's ServiceMonitor will also select `port: http`, so fix this before anything else builds on it, and while 0.1.0 is unreleased so the meaning of the value can still change for free.
  - **Remediation shape (one fix block, chart-only):** separate the Service port from the listen port. Either (a) hard-code `containerPort: 9221` and keep `service.port` as Service-only (`targetPort: http` already makes this work), or (b) add a separate container-port value and render `--web.listen-address=[::]:<port>` into args ahead of `extraArgs`. Option (a) is smaller. Option (b) needs the flag confirmed against v3.11.0. Fix the `values.yaml:56` comment. Replace the test at `deployment_test.yaml:43-49` with one that asserts `service.port: 9300` gives Service port 9300 and container port/probes still on 9221/`http` (for (b): the args contain the matching listen address). NOTES.txt already uses `service.port` for the Service, which is correct under both options.
  - Makefile `deps` (`07bcc49`, soundness only, not blocking): the approach works. Bitnami/dex repos are added from `Chart.yaml`, `helm dependency build` honours the committed `Chart.lock`, and `charts/*/charts/` is gitignored with no subchart files previously tracked. Three notes: (i) the commit title and the DEVLOG say `lint` **and** `test` depend on `deps`, but in the Makefile `test` has no prerequisite. `deps` hangs off `helm-unittest` (plugin install) instead, so `make init` now needs network access to Bitnami.
